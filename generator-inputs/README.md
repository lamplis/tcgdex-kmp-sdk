# Generator Inputs Contract

This directory is the canonical artifact contract for Cardium database generation.

## Canonical layout

- `cardmarket/cardmarket-prices-<lang>.json` (`de`, `en`, `es`, `fr`, `it`, `pt`)
- `missing-cards/missing_cards.json`
- `pokepedia/missing-fr-card-images-tree.json`
- `pokepedia/missing-fr-card-images-unresolved.json` (generated by the DB generator)

## Ownership

- **Producer repo:** `poke-browser`
- **Consumer module:** `cardium/libs/tcgdex-kmp-sdk`

## Configuration precedence

For both producer and consumer scripts, path resolution follows:

1. CLI flag / Gradle property
2. Environment variable
3. Canonical repo-local default (this directory)

## Canonical commands

From `poke-browser`:

```bash
bash scripts/export-unified.sh --cardium="/path/to/cardium"
bash scripts/export/full-export-to-cardium.sh --cardium="/path/to/cardium"
```

From `cardium`:

```bash
./scripts/regenerate-database.sh
./gradlew :libs:tcgdex-kmp-sdk:generateTcgdexDatabase -Ptcgdex.force=true
./gradlew :libs:tcgdex-kmp-sdk:generatorE2eTest
./gradlew :libs:tcgdex-kmp-sdk:jvmTest
```

`generatorE2eTest` runs the SQL end-to-end assertion that generates a temporary `tcgdex.db`
and verifies a deterministic missing-image card is enriched with Cardmarket pricing and
Pokepedia fallback metadata.

## Migration notes

- Legacy `cardium/exports/prices` and `cardium/exports/missing-cards` are compatibility-only.
- Legacy `libs/tcgdex-kmp-sdk/resources/pokepedia` is compatibility-only.
- New work must target `generator-inputs/` directly.

### Marketplace ID migration (thirdParty)

`cards-database` is progressively migrating Cardmarket/TCGPlayer product IDs from
the card root (`thirdParty.cardmarket`) to per-variant objects
(`variants_detailed[].thirdParty.cardmarket`). Both schemas coexist during
migration and the generator resolves the Cardmarket product ID using deterministic
precedence:

1. `variants_detailed[]` entry with `type: "normal"` and `thirdParty.<marketplace>`
2. Root-level `thirdParty.<marketplace>` (legacy)
3. First non-normal variant in `variants_detailed` that defines the marketplace ID

This ensures pricing continues to work for both migrated and unmigrated cards.
Once migration completes, the root-level `thirdParty` lookup becomes a no-op
fallback.
